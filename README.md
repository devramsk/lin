# LineageOS 21 pre-QPR2 Light GSI: сборочная обвязка

Это **не архив всех исходников Android**: дерево загружается `repo` в один отдельный рабочий каталог на сборочной машине. В Git не помещаются сотни гигабайт исходников и бинарные образы. Используются официальный манифест `LOS21-pre-QPR2/android` (`lineage-21.0`) и два upstream-репозитория AndyCGYan; ревизии скриптов и патчей зафиксированы в `scripts/build-gsi.sh`. Ветка манифеста и проекты могут изменяться; полученный `audit/resolved-manifest.xml` записывает фактически проверенные ревизии, но патчи и `repopick` создают локальные коммиты, которых может не быть на удалённом сервере. Это не полная гарантия воспроизводимости.

## Запуск

Нужна выделенная машина Ubuntu 22.04 x86_64: рекомендуется не менее 64 ГиБ RAM и 400 ГиБ свободного места на SSD, дополнительно место для двух образов. Требуются доступ к GitHub, GitLab, серверам LineageOS/Gerrit, Google repo и зеркалам из манифеста; одного доступа к GitHub недостаточно. Нужен `sudo` без интерактивного пароля для установки пакетов. Точная команда:

```bash
BUILD_ROOT="$HOME/lineage-21-gsi-$(date +%s)" bash scripts/build-gsi.sh
```

Скрипт устанавливает пакеты, `repo` и Git LFS, создаёт чистый HOME, инициализирует манифест, клонирует инструменты и запускает именно `bash lineage_build_unified/build_unified.sh treble 64VN 64GN`. Upstream сам синхронизирует исходники, применяет патчи и собирает варианты последовательно. Скрипт принципиально отказывается использовать существующие `source`/`home`: upstream вызывает `git clean -fdx` и `git reset --hard` в проектах. Сборка неподписанная, без личных ключей и без `personal`. `64GN` использует MindTheGapps; проверьте применимые лицензии до распространения. Артефакты в `$BUILD_ROOT/home/build-output/`, контрольные суммы и журналы в `$BUILD_ROOT/audit/`. Используйте новый BUILD_ROOT при повторе; удаление старого каталога выполняется только владельцем вручную.

Для заранее подготовленной Ubuntu-машины можно задать `INSTALL_DEPS=0`. Проверка свободного места регулируется `MIN_FREE_GIB`, но её уменьшение не уменьшает реальные потребности сборки. В процессе сборки раз в минуту пишутся время, диск и память; `build.log` содержит полный вывод. Это мониторинг и сведения о происхождении, а не независимый полный аудит безопасности исходников. Итоговый статус записывается при обычном завершении или ошибке; при принудительном завершении или отмене не гарантируется.

## GitHub Actions

Workflow запускается вручную (`workflow_dispatch`), не на PR или push. Установите **одноразовый, изолированный** self-hosted Linux x86_64 Ubuntu 22.04 runner с меткой `lineage-gsi`, достаточными ресурсами, открытым доступом ко всем источникам и `sudo -n` для apt. На публичном репозитории self-hosted runner особенно опасен: запускайте только доверенный код/ветки, ограничьте доступ и не храните секреты на машине. Стандартные GitHub-hosted runner обычно не подходят по ресурсам и имеют лимит 6 часов; self-hosted задача ограничена здесь 72 часами. После регистрации runner запустите workflow из вкладки Actions на нужной ветке. Файлы журнала загружаются даже при ошибке, образы — только после успешной проверки обоих вариантов. Большие образы могут превысить квоты артефактов GitHub или тарифицироваться; успешная компиляция и успешная загрузка — разные этапы. При прерывании артефакты не гарантированы. Исходное дерево и образы остаются на диске runner до ручной очистки.

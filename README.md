# LineageOS 21 pre-QPR2 Light GSI — бесплатный GitHub-hosted Actions

Цель — неподписанные образы `64VN` и `64GN`. Android-дерево загружается `repo` в отдельный рабочий каталог; сотни гигабайт исходников и образы не включены в Git. `64GN` использует MindTheGapps — проверьте лицензии перед распространением.

## Статус и ограничения

Workflow использует **только** стандартный GitHub-hosted `ubuntu-22.04`; self-hosted runners не используются. Для публичного репозитория стандартный Linux runner специфицирован как 4 CPU, 16 GB RAM и 14 GB SSD. В действительности свободное пространство измеряется при запуске и может отличаться. LineageOS рекомендует для версии 21 около 400 GB свободного диска и 64 GB RAM. GitHub-hosted job ограничен шестью часами и его VM уничтожается после завершения.

Режим `build` больше не требует 400 GiB: он пытается выполнить сборку независимо от свободного места и записывает состояние ресурсов. На стандартном runner есть высокий риск нехватки места, памяти или времени. Полная сборка в заданных ограничениях **не подтверждена**, готовых образов нет; прохождение `probe` не означает сборку.

`/tmp` на runner не сохраняется между заданиями. Стандартный лимит GitHub Actions cache — 10 GB на репозиторий; использование cache как надёжного хранилища полного дерева и всех промежуточных файлов для этой сборки в указанном бесплатном ограничении не реализовано и не проверено. Простое разделение на шаги или Git-коммиты не увеличивает объём диска и не сохраняет VM. Не используйте workflow как подтверждённый способ продолжить сборку после смены job.

## Как запустить и предоставить Arena доступ

В этой сессии Arena уже смогла отправить изменения в текущую ветку и запустить Actions — для этого никаких токенов в чате не требуется. Если доступ перестанет работать, переподключите GitHub в Arena и разрешите GitHub-приложению доступ к этому репозиторию; владелец может подтвердить запрос приложения через **GitHub Settings → Applications → Installed GitHub Apps**. Для отправки файлов workflow нужны Contents и Workflows write, для запуска workflow — Actions write; для чтения результатов — Actions read. Для ручного запуска в интерфейсе необходим write-доступ к репозиторию. Не передавайте в чат пароли, токены или регистрационные данные.

1. Откройте репозиторий → **Actions → LineageOS 21 pre-QPR2 GSI → Run workflow** и выберите ветку с этими изменениями. Сам файл workflow должен существовать в default-ветке; он уже там есть.
2. Выберите `mode=probe`, чтобы выполнить проверку скриптов, замер ресурсов и параллельную инвентаризацию зафиксированных upstream-репозиториев. `mode=build` дополнительно пытается запустить полную поэтапную сборку и может завершиться ошибкой при нехватке ресурсов.
3. В job `upstream-inventory` сохраняется небольшой artifact с XML-инвентарём, ревизиями и Git bundle отчёта. Это не исходный Android целиком и не полный независимый аудит безопасности. В job `build` журналы и оба образа загружаются отдельно; квоты/лимиты артефактов могут помешать их сохранению.
4. Для диагностики откройте job и проверьте его статус и журналы; при успехе скачайте artifacts. Отмена/таймаут не гарантируют выгрузку логов. Для определения достигнутого этапа проверяйте логи и артефакты конкретного запуска.

## Скрипты и контрольные точки

- `scripts/build-gsi.sh` устанавливает компоненты, инициализирует манифест и запускает точную команду `bash lineage_build_unified/build_unified.sh treble 64VN 64GN` в чистом отдельном каталоге. Он не проверен полной сборкой.
- В Actions `scripts/staged-build-gsi.sh` экспериментально разделяет подготовку и два вызова upstream `treble nosync 64VN` / `treble nosync 64GN`; эквивалентность единому вызову реальной сборкой не подтверждена. Этапы: setup, sync/repopick/patches, каждая сборка, валидация двух образов. Upstream применяет `git clean -fdx`, `git reset --hard`, `git am`: не используйте личное дерево.
- Микрозаписи о ходе сначала пишутся в `/tmp`, затем перемещаются в `audit/events` и коммитятся в отдельный локальный `audit/.git`; параллельно фиксируются ресурсы и логи. Коммиты не содержат все исходники, промежуточные файлы или образы. При обычном завершении или ошибке bundle и журналы могут быть загружены как artifact, но это **не checkpoint для восстановления сборки**. На постоянном диске прежняя обвязка может пропускать завершённые стадии, но это не сохранит данные стандартного GitHub-hosted job. Незавершённые подготовительные этапы автоматически не повторяются из-за риска повреждения дерева.
- `scripts/audit-upstream.sh` клонирует только два небольших репозитория AndyCGYan и манифест, проверяет доступность зафиксированных SHA, разбирает локальный манифест и считает файлы патчей. Ветки манифеста движутся, repopick/patches создают локальные коммиты; даже сохранённый `repo manifest -r` не гарантирует воспроизводимость.
